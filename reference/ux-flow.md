## 1. 製品の3本柱（最終形態の定義）

BRAST は「スライドを作る道具」ではなく **ブランドの憲法に統治された、自律ブランドストラテジスト**。

1. **ブランド運用ルール（ガバナンス層）** ★新 ― ブランドの憲法。これに反する戦略・コンテンツ・外部指示は跳ね返す。これが無いと「何でもあり」になり、出力が正しいと言える基準が無い。
2. **グラスボックス（推論が辿れる）** ― 根拠（ナレッジ＋トレンド信号＋競合の空白）→ 結論（戦略→コンテンツ）まで全部辿れる。スライドは氷山の一角、価値はその下の推論。
3. **閉じたループ** ― 提案 → 修正 → 承認 → 実行 → 結果計測 → 翌週反映 を行き来できる。

現プロトタイプ（M1〜M4）は柱2の「出力（スライド）」だけ実装済みで、柱1が無く、柱2の推論と柱3のループがスタブ。本ブラッシュアップでこの3本柱を立てる。

## 2. エンドツーエンドのUXフロー

### 2-A. 初期セットアップ（テナント単位・1回）
```
ナレッジ投入(ウェブ/資料)
  → AIがベースナレッジを構築（SWOT/ポジショニング等）
    → ★AIがブランド運用ルールを提案（出面戦略＋ガードレール＋KPI）
      → 人間が承認・編集して確定   ← 山本さんの「セオリー」
        → AIがトレンド/競合の追跡対象を自動設定（人間が修正可）
```
ポイント：ルールも出面も**まずAIが提案**し、人間は承認/編集する（白紙から作らせない）。出面提案には「この情報には専用メディアサイトを新設すべき」まで含む。

### 2-B. 毎週のループ（運用）
```
月06:00 自動: トレンド/競合 再調査
  → 戦略導出(S1〜S6, strategy-logic.md) ＝推論グラフが進行
    → 週次ブリーフィング（推論グラフ＋7スライド）を提示
      → 人間レビュー:
          ・全体承認 → 実行
          ・スライド/工程を差し戻し → 原因ノードから下流だけ再実行
          ・個別コンテンツを開いて「ここをこう直して」（content-edit chat）
            → 指示が規範違反なら押し返し
      → 承認 → 配信(自動/手動)
        → 実行・結果計測（リーチ/CV/期待値到達）
          → 翌週の戦略へ反映（採用済みでもトレンド変化で更新提案）
```

## 3. 画面インベントリ（◆=新規/大改修、○=既存を配線強化）

### ◆ ブランド運用ルール（Brand Operating Rules）★柱1・新規
- **目的:** ブランドの憲法を定義・可視化。戦略以降すべての制約源。
- **要素:**
  - 出面(チャネル)戦略：現チャネル一覧＋役割。AI提案の「新メディアサイト立ち上げ提案」（理由つき）。
  - ガードレール：必須事項/禁止事項（トーン、薬機法・景表法、主張の制約）。
  - KPI：定常=認知・信頼、キャンペーン=CV 等の指標定義。
  - 各ルールは AI提案 → 人間が承認/編集。改訂履歴を持つ。
- **状態:** 提案中 / 承認済み / 編集中。

### ◆ 週次ブリーフィング（Briefing）＝推論グラフ ＋ スライド ★柱2・大改修
- **目的:** その週の戦略を、根拠から結論まで辿れる形で提示。
- **構成（重要な変更）:**
  - **上段：推論グラフ**（Salesforce 的プログレス）= `strategy-logic.md` の S1〜S6。
    各ステージをクリック→「入力した根拠/適用ルール/出した結論」。現在の「思考プロセス（ステータスバー）」をこれに格上げ。
  - **下段：7スライド**（既存）= 各ノードの詳細表示。スライドの主張から根拠へドリルダウン（← bet ← opportunity ← signal実データ）。
  - 右/下：フィードバック（部下に指示する）。差し戻し→原因ノードから下流再実行。
- **状態:** 自走済み・承認待ち / 差し戻し中 / 承認済み・実行中。

### ◆ コンテンツ詳細 ＋ 修正チャット（Content Detail + Edit Chat）★柱2/3・新規（修正点②）
- **目的:** 個別コンテンツを*読みながら*、見ている場所で「ここをこう直して」と指示。
- **要素:**
  - 本文プレビュー（記事/SNS）、スコア、4体レビュー結果、生成元 bet への逆リンク。
  - インラインの修正チャット：指示 → 原因工程（生成 or 該当レビュアー）へ自動ルーティング。
  - **ブランド押し返し:** 指示が規範違反なら「ルール X に反します。実行しますか？」（S5を噛ませる）。
  - 旧版 vs 新版の並列提示（戦略変更でリライトされた場合）。

### ◆ 実行・結果（Execution & Results）★柱3・新規（修正点③a/b）
- **目的:** 実行プロセスの確認と、実行済み戦略の結果レビュー（＝ループを閉じる）。
- **要素:**
  - 実行中：いま何が配信進行中か、各チャネルの状態。
  - 結果：週ごとの戦略シートを開くと、リーチ/CV/期待値到達が出る。Slack日次レポートと接続。
  - 「期待値に届いた/届かない」を人間が評価 → 翌週戦略への学習に反映。

### ○ 戦略アーカイブ（Strategy Archive）
- 週次戦略シートが積み上がる（実行済み/予定）。各週を開くと推論グラフ＋結果へ。実行結果の表示を追加。

### ○ ブランドナレッジ（Knowledge）／○ トレンド・レーダー（Trends）★配線強化（修正点③c）
- 既に*存在はする*が、briefing の主張からクリックで根拠へ飛ぶ配線が無く中身が薄い。
- **「存在する」→「戦略の根拠として辿れる」へ。** 推論グラフの signal/knowledge ノードからこのタブの該当データへジャンプできるようにする。
- トレンドは関連度の*理由*（concept match reason）を表示し、無関連を落とした根拠も見せる。

### ○ チャネル（Channels）／○ エージェント（Agents）
- 既存維持。チャネルはブランド運用ルールの出面戦略と同期。エージェントは閲覧のみ。

## 4. 横断インタラクション

- **ドリルダウン/トレース:** あらゆる結論は根拠へ逆リンク。これが柱2の本体。
- **差し戻し→下流再実行:** 推論グラフの任意ノードへ戻り、そこから下流のみ再実行。承認済みは残す。
- **ブランド押し返し:** 戦略・コンテンツ・*外部からの修正指示*が規範違反のとき確認を出す（柱1×柱2の接点）。
- **AIによる提案先行:** ルール・出面・追跡対象・戦略すべて、まずAIが提案→人間が承認/編集（白紙にしない）。
