# レビュー会の確定事項ダイジェスト (review-meeting-decisions.md)

> プロジェクトメンバー（岡本・Long・山本）でプロトタイプをレビューした回の要点を構造化したもの。
> **原典のニュアンスは `meeting-transcript-2.md`（全文）で補うこと**（この文書は要約なので平板化している可能性がある）。

## 1. 製品の重心の再確認
- BRAST は「メディア生成器」ではなく **Brand Strategy OS**。ブランドの憲法（運用ルール）に統治されるべき。
- 現プロトタイプは「戦略を提案する一機能」に偏っており、根拠ロジックとループが見えない → 「何を根拠に正しいか」が判断できない、という評価。

## 2. 新たに合意した第3の柱：ブランド運用ルール（山本さんの指摘）
- 「ブランドロジックに適わない外部指示が来たとき、ちゃんと跳ね返せるか」を検証すべき。
- そのためには **ブランド運用ルールを先に設定するステップ**が要る（現状は無い）。
- フロー合意（セオリー）: ナレッジ投入 → **AIがブランドルールを提案** → 人間が承認/編集 → それに照らして戦略を出す。
- 出面(チャネル)も AI提案先行。提案には「この情報には専用メディアサイトを新設すべき」まで含む。
  → サイト立ち上げプロセス自体も BRAST 内に持つ方向（記事生成だけのツールから一段上げる）。

## 3. Long さんのブロッカー（最重要）
- 情報の習得（Web＋TikTok/YouTube/SNS/ニュース/検索順位）はできている。
- 「習得した情報を、**どういうロジック/アルゴリズムで戦略に紐づけるか**」が決まらず、戦略画面が作れず止まっている。
- 岡本さんが「ロジックを整理して Long さんに送る」と合意 → それが `strategy-logic.md`。

## 4. 実機で見えた品質課題
- リサーチが無関連結果を拾う（BCPで「仙台市議会中継」「アパレル備品管理DX」等）。原因はキーワード一致。
  → 概念理解での関連度フィルタが必要（strategy-logic.md S1）。
- 画像生成の精度が低い → 改善が必要（Phase 2寄り）。

## 5. 岡本さんの3つの修正点（前段で整理済み）
1. 思考プロセス/ロジックの可視化（Salesforce 的プログレス＋ドリルダウン）。
2. 個別コンテンツの修正チャットUXが無い → 操作に迷う。
3. 全体UXの一巡性が無い（実行済み結果画面 / 実行プロセスのレビュー / ナレッジ・トレンドの根拠タブ）。

## 6. 当面のアクション分担
- 岡本さん: ①戦略導出ロジックの整理 → Long へ（= strategy-logic.md）。②ブランド運用ルールのモック → Long へ。
- Long: 上記を受けて戦略画面とルール層を実装。
- プロトタイプUIの差分修正は、本パッケージ（M5〜M9）で対応。
