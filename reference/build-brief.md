## M5 — ブランド運用ルール層（柱1・新規）

```
ux-flow.md §3「ブランド運用ルール」と §2-A を正として実装する。

1. 新画面「ブランド運用ルール」をナビに追加（ナレッジの直後）。
2. 内容: ①出面(チャネル)戦略（現チャネル＋役割、AI提案の「新メディアサイト立ち上げ提案」を理由つきで）

4. データは src/data/ にテナント別ダミーで。型は types.ts に BrandRules を追加。
5. パイプライン②として位置づけ、以降の戦略の制約源になることをデータ構造上つなげておく
   （実際のチェックは M7 で接続）。

JRC医療ITテナントで具体的なダミー（薬機法配慮・ORCA出面・CV/信頼KPI）を入れて。

## M6 — 推論グラフ（柱2・思考プロセスの格上げ）★キーストーン

```
strategy-logic.md の S1〜S6 を正として、現在の「思考プロセス(ステータスバー)」を
「推論グラフ」に作り替える。これがこの製品の生命線。

1. 週次ブリーフィングの上段に、S1→S2→S3→S4→S5→S6 のステージ進行を
   Salesforce のプログレスバー的に表示（各ステージ=ノード）。
2. 各ノードをクリックすると「入力した根拠 / 適用したルール・重み / 出した結論」を表示。
   strategy-logic.md のデータ構造（ScoredSignal/Opportunity/StrategyBet/...）に沿う。
3. ドリルダウン: スライドの主張 → その StrategyBet → 元の Opportunity → 元の Signal(実データ)
   へ逆リンクで辿れるようにする。7スライドは各ノードの「詳細表示」に位置づけ直す。
4. WeeklyStrategy に reasoningTrace（S1〜S6の inputsRef/operation/outputsRef）を持たせ、
   それを描画する。データはダミーで良いが、逆リンクが実際に辿れること。
5. 差し戻しは「推論グラフの任意ノードへ戻り、下流だけ再実行」に統一。

目的: 「このアウトプットは何を根拠に正しいか」が常に辿れる状態にする。
```

## M7 — コンテンツ修正チャット ＋ ブランド押し返し（修正点②）

```
ux-flow.md §3「コンテンツ詳細＋修正チャット」を実装する。

1. メディアプランの各コンテンツのタイトルをクリック→コンテンツ詳細を開く
   （本文プレビュー、スコア、4体レビュー結果、生成元 StrategyBet への逆リンク）。
2. 詳細の中に「インライン修正チャット」を置く。見ている場所で「ここをこう直して」と指示できる。
3. 指示は原因工程（コンテンツ生成 or 該当レビュアー）に自動ルーティングし、推論グラフ上で
   該当ノードをハイライト→下流再実行（M6と接続）。
4. ★ブランド押し返し: 指示が M5 のガードレールに反する場合、
   「ルール◯◯に反します。それでも実行しますか？」と確認を出す（strategy-logic.md S5を噛ませる）。
5. 旧版vs新版の並列提示（戦略変更でリライトされた場合）も詳細に統合。
```

   「存在する」ではなく「戦略の根拠として辿れる」状態にする。
4. トレンドは relevance の理由（concept match reason）と、無関連を落とした根拠も見せる。
```
