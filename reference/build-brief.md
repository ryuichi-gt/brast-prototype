## M1 — 雛形 + デザイントークン + 週次ブリーフィング画面

```
まず CLAUDE.md を読んで。これがこのプロジェクトの確定仕様。
次に reference/brast-mockup.html を読んで。これが UI の正（レビュー済みの画面仕様）。
意図の背景を確認したいときだけ reference/meeting-transcript.md を参照して（自動文字起こしでノイズが多いので鵜呑みにしない）。

BRAST は「AIが週次でメディア戦略を作り切ってプレゼンしてくる、超優秀な部下」というUXのプロダクト。

M1としてやること（この順番で）:
1. Next.js (App Router) + TypeScript + Tailwind CSS でプロジェクトを scaffold
2. mockup の配色・タイポ・余白をデザイントークン化して globals.css に集約。
   色の意味付けを厳守: teal = AIの自律/ライブ, amber = 人間の判断が必要。
3. 左ナビ（テナント切替 + 7項目）と上部バーの共通レイアウトを実装
4. 「週次ブリーフィング」画面を実装:
   - 中央: 紙のデッキ（7スライド: サマリー/ナレッジ状態/トレンド/競合/戦略/メディアプラン/配信スケジュール）
   - 右: 思考プロセス（エージェントのパイプライン9工程）
   - 下: フィードバック dock
   - データは src/data/ のダミーJSONから流し込む（バックエンド接続はしない）
5. Vercel にプレビューデプロイできる状態にして PR を作成

ルール: コードとコメントは英語。localStorageは使わない。
1ステップ終わるごとに簡潔に報告して。迷う仕様はダミーで進めて「要確認」と書いて。
```

## M2 — トレースバック → 下流再実行のインタラクション（最重要）

```
M2。週次ブリーフィングの中核インタラクションを実装する。

- 各スライドに「このスライドを直す」を付ける。
- 押すと、そのスライドを生んだ原因のエージェント工程を右のパイプラインでハイライトし、
  そこから下流の工程だけを「再実行できる」状態にする（既に承認済みの記事は残す）。
- フィードバック dock に自然文で指示を打つと、内容から該当工程を推定して同様に遡る。
- スライド→担当エージェント工程の対応は mockup の挙動に合わせる。

挙動は reference/brast-mockup.html を正として再現して。完了したら PR を更新して報告。
```

## M3 — 残りの画面

```
M3。残りの画面を mockup に合わせて実装する（1画面ずつ、各完了で報告）:
1. 戦略アーカイブ（週次戦略シートが積み上がる: 実行済み/予定）
2. トレンド・レーダー（ライブ信号 + レーダー表示）
3. ブランドナレッジ（差分検知: fresh/更新候補）
4. コンテンツ（配信予定/配信済み。戦略変更時は旧版vs新版を並列提示し選択できる）
5. チャネル（複数メディア一元管理。役割の可視化。自動連携 vs 手動）
6. エージェント（オーケストレーションのパイプライン。中身は閲覧のみ・編集不可）

各画面ともダミーJSON駆動。完了ごとに PR 更新と報告。
```

## M4 — テナント切替 + レスポンシブ仕上げ

```
M4。仕上げ:
1. テナント切替（SympaFit / JRC医療IT / ツズリーBCP / Libero）とチャネル切替を機能させる。
   テナントごとにダミーデータを切り替える。
2. レスポンシブを仕上げる（PC/タブレット/スマホで崩れない。スマホでは思考プロセスとdockをデッキの下にスタック）。
3. アクセシビリティ: キーボードフォーカス可視、prefers-reduced-motion 尊重。

完了したら、現状の実装範囲と「Phase 2(DIGITRAN)へ引き継ぐべき項目（バックエンド接続・実データ・Agent SDK連携・SNS OAuth・配信）」を README にまとめて。
```
